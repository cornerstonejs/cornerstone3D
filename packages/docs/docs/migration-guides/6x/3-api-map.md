# Every legacy call and what replaces it

Search this page for the name that your code uses. Each name has a row in the
table of its group. The row gives the call to use in 6.0.

The groups up to [The type of a viewport in 6.0](#the-type-of-a-viewport-in-60)
are for code on 5.x. Code that already runs on a 6.0 beta reads
[Names changed since 6.0.0-beta.2](#names-changed-since-600-beta2).

**State.** The calls in the column "Use instead" are in the code, on the next
viewports, and so is the removal: on 6.0 the legacy classes, types, settings
and helpers that the rows name are gone. See
[Next viewports only](./1-next-viewports-only.md).

## How to read a row

- **Legacy** is the name in 5.x. In the sections of
  [Names changed since 6.0.0-beta.2](#names-changed-since-600-beta2) it is the
  name or the behaviour of 6.0.0-beta.2.
- **6.0** says what happens to the name:
  - **Same name**: the next viewport of that family has the member and it
    means the same. Where the meaning or a default differs, the last column
    starts with "Differs".
  - **Replaced**: the name is gone. Another call does the job.
  - **Removed**: the name is gone and no call takes its place. The row says
    why, and what to do.
  - **Changed**: the name stays and what it does changes. The last column
    says how.
  - **New**: a call or an export that 6.0 adds. The column "Legacy" has the
    code that it replaces, or `-`.
  - **Deprecated**: the name still works in 6.x and means the same as the
    name in "Use instead". Move to that name.
- **Use instead** is the call, as code. `viewport` is a next viewport.
  `displaySetId` is the id that the application registered, see
  [A display set is registered once](./1-next-viewports-only.md#a-display-set-is-registered-once).
- **What it does** says in one line what the call does.
- **Access** is **Public** for a member of the viewport, an event, or a name
  exported from `@cornerstonejs/core` or `@cornerstonejs/tools`. It is
  **Private** for a name inside the library that an application cannot
  import.
- **Stack and volume, notes**: a planar viewport shows a stack of 2D images
  or a volume. `viewport.getCurrentMode()` is `'stack'` or `'volume'`. The
  column says what the call does in each mode.

`utilities`, `cache`, `viewportProjection`, `eventTarget` and `Enums` are
those of `@cornerstonejs/core`, unless the row names the tools.

## Viewport types

The plain names are in the code, in `Enums.ViewportType` and
`Enums.ViewportTypes`: `PLANAR` (`'planar'`), `VOLUME_3D` (`'volume3d'`),
`VIDEO` (`'video'`), `WHOLE_SLIDE` (`'wholeSlide'`) and `ECG` (`'ecg'`). Each
gives the viewport of its family, and that string is its `viewport.type`.
The 5.x `_NEXT` names and `*Next` strings are gone, as are `STACK`,
`ORTHOGRAPHIC` and `PERSPECTIVE`: see the rows below.

An application that ran legacy and next viewports side by side on 5.x may
test for a legacy type: `type === ViewportType.VOLUME_3D` was false for a next
3D viewport there (its type was `'volume3dNext'`). In 6.0 both names have the
value `'volume3d'`, so the same test is true for every 3D viewport, and
`type === VOLUME_3D || type === VOLUME_3D_NEXT` is one comparison after the
codemod. Read each such test again: the branch for the legacy viewport goes.
