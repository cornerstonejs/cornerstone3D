# v6: open issues of the move to the next viewports

These are the issues that the work on Cornerstone3D 6.0 (the removal of the legacy
viewports, branch `feat/slice-first-step-1`) found along the way. Each row says what was
seen, how (measured or read), where, and what to do; the State column says what became
of it. The list was started on 17 November 2026 and closed on 21 November 2026.

State on 21 November 2026, 114 rows:
- fixed (103): each with a test that failed first; the commit or package is named in
  the row; rows 8, 9, 39, 46, 90, 91, 96 and 97 by the owner's decisions of 20
  November, rows 101 to 109 from the external review of 20 November, row 112 from
  the owner's iPhone, row 113 from the OHIF upgrade;
- decided or documented (9): left as they are on purpose (5.x did the same, the
  6.0 API does it by design, or the owner decided so), with a line in the 6.0
  migration guide where an application sees it; rows 15, 36, 86, 88 and 89 by the
  owner's decisions of 20 November;
- open (2): row 111, statistics on a labelmap over a video, which nothing had
  before 6.0; row 114, repository paths in the built declaration files, as in 5.x.
  Neither blocks 6.0.

## How to work on one of these

1. Write a test that fails on the code as it is. For the planar viewport: one test in
   stack mode and one in volume mode (`packages/core/test/utils/planarSeriesBothModes.js`
   mounts one series both ways). Use karma (`*_test.js`) for anything that needs a real
   viewport, jest (`*.jest.js`) where a stand-in is enough.
2. If the test passes, the issue is not there. Keep the test and change no code.
3. Fix it in the new viewport classes
   (`packages/core/src/RenderingEngine/GenericViewport/`) or in the tools. Do not add a
   member with a legacy name to a new class, and no new event name.
4. Checks, from the repository root, with Node 24
   (`export PATH="$HOME/.nvm/versions/node/v24.15.0/bin:$PATH"`):
   ```sh
   (cd packages/core && npx tsc --noEmit -p tsconfig.json && npx jest -c jest.config.js)
   (cd packages/core && npx tsc --project ./tsconfig.json && npx tsc-alias -p ./tsconfig.json --resolve-full-paths && node ../../scripts/write-dist-esm-package-json.js ./)
   (cd packages/tools && npx tsc --noEmit -p tsconfig.json && npx jest -c jest.config.js)
   node_modules/.bin/oxlint packages/core/src packages/tools/src --quiet
   npx karma start --single-run
   npx karma start karma.decoders.conf.js --single-run
   ```
5. If an application can see the change, add a line to the 6.0 migration guide
   (`packages/docs/docs/migration-guides/6x/2-rendering-changes.md`).

"Measured" means a test or a run showed it. "Read" means it was seen in the code and
not run.

## Gone with the legacy viewports and the adapters

These went away when stage 5 deleted the legacy viewports and the adapters (19 November
2026). They are kept so that nobody looks for them again.

- A zoom and pan synchronizer between a legacy viewport or an adapter and a new 3D or
  whole slide viewport does not move the new one.
- A new colour of a segment does not show on a surface on the legacy 3D viewport or on
  the adapter. It shows on the new viewport.
- `removeSurfaceFromElement` on a legacy viewport removes every actor whose
  representation UID starts with the segmentation id, a labelmap actor too.
- The adapter in volume mode fires `STACK_NEW_IMAGE`, which the legacy volume viewport
  never fires, and fires both new image events twice at a mount.
- On a legacy viewport and on the adapter the cropping handles stay in the scene after
  the tool is disabled.
- `Types.IEnabledElement['viewport']` is typed as the legacy pair. Widening it gives 170
  errors in 73 files of the tools. That is the type work of the removal.
- Places where an adapter does not do what its legacy class did, found when the classes
  were deleted. Old examples on the adapters can show them until they are converted:
  - the 3D adapter: `setBlendMode` does nothing; a camera read after `addActor` with no
    volume is not usable; `VOI_MODIFIED` has no `invertStateChanged`;
  - the planar adapter on a volume: a list in `colormap.opacity` is read over the
    window (`[0, 0, 25.2, 0.8]` where the class read `[0, 0, 0.1, 0.8]`); it has no
    `getSlicesClippingPlanes()` and no `getCurrentSlicePixelData()`;
  - the ECG adapter opens in the layout of the new viewport, not in 12 rows;
  - the whole slide and the ECG adapter give a view reference without
    `viewPlaneNormal`, `viewUp` and `planeRestriction`;
  - the video adapter has no `videoElement` member.

## Where the details are

Each fix is a commit on the branch whose message says what was measured, what 5.x did and
what changed; `git log --grep '<package>'` with the package named in the State column
finds it. The 6.0 migration guide (`packages/docs/docs/migration-guides/6x/`) has every
change an application sees.
